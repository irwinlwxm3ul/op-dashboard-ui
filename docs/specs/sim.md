# Module spec: sim

Owned paths: src/shared/sim/** (except view.ts, which is a fixed contract) and tests/sim.test.ts, tests/runner.test.ts

- MODULE: Game simulation + match runner (src/shared/sim). Implement GameSim (implements SimView from sim/view.ts) and MatchRunner exactly per ARCHITECTURE.md Stage B, exported from src/shared/sim/index.ts (also re-export the view.ts types). Split into focused files (e.g. GameSim.ts, players.ts, combat.ts, projectiles.ts, lagcomp.ts, zone.ts, plane.ts, loot.ts, vehiclesSim.ts, training.ts, snapshot.ts, MatchRunner.ts).

- IDs: one counter for all entities (players, vehicles, loot, projectiles). Teams 0..ceil(maxPlayers/teamSize)-1. addPlayer with explicit team (if it has room) else first team with room; returns -1 when full or match already started in br mode (training: always allowed, spawns immediately). fillBots fills remaining slots with bots (names via an internal list of original gamer tags; bots module will provide botName but do not depend on it). removePlayer: connected=false, isBot=true (bot takes over so squads are not left hanging).

- Match flow (br): start(): phase plane, plane path deterministic from seed: random heading, line through a point within 200 m of the island center, start/end beyond the map edges, altitude PLANE_ALTITUDE, speed PLANE_SPEED. All players mode plane riding at the plane position (no physics). Action jump allowed once the plane is over the map (world.inBounds) -> mode freefall at plane position (+ small backward offset), jumpY recorded; players still aboard auto-eject when the plane is 90 percent along its path. Freefall/parachute via physics stepDrop; action chute opens if jumpY - pos.y >= MIN_CHUTE_DROP; auto-open at AUTO_CHUTE_HEIGHT above world.groundAt. Landing -> mode ground (events land / chuteOpen / jumpPlane). Phase becomes playing once nobody is in the plane. Zone: 8 phases (wait s, shrink s, radius m, damage/s): (100,90,320,0.4) (80,60,200,0.6) (70,50,120,1.0) (60,40,70,2.0) (50,35,40,3.5) (40,30,20,5) (30,25,8,8) (20,20,0,12), timings multiplied by config.zoneSpeed; zone starts when the plane starts with an initial circle covering the whole map (stage pre then waiting). Each next circle lies fully inside the current one with its center on land (retry with seeded rng). Outside the current circle players take damagePerSec (ignores armor; downed players bleed faster). Events zonePhase on every stage change.

- Player tick (consume at most ONE queued input per tick; if none, repeat the last input but clear actions and edge-triggered buttons): apply aim (base yaw/pitch), stance (via physics canStand; prone/crouch speeds), movement via physics stepCharacter (ground/swim) or stepDrop (freefall/parachute) with speedMul = active weapon moveSpeedMul x ADS slow (0.65 at full ADS) x healing moveMul x boostSpeedMul; sprint cancels ADS and is cancelled by firing; slot switching with drawTimer (cancels reload/use); ADS blend at 1/adsTime; reload (R or auto when firing with empty mag and reserve) with tactical/empty times, shotgun shell-by-shell (interruptible by firing); firing per fireMode (semi/bolt/pump need trigger edge; auto holds) with fireCooldown = fireInterval; dryfire event on empty; shot seed = hash32(playerId, shotCounter); effective aim = base + server recoil (recoilPitch/recoilYaw); spreadCone with ctx (ads, speed, airborne, stance, bloom); shotDirections; recoilForShot accumulates into recoilPitch/Yaw (server authoritative), sprayCount resets after trigger release > 1.5x fireInterval, bloom decays; recoverRecoil every tick. No firing in plane/freefall/parachute/swim, while downed, during draw/reload/use, or from vehicle seats that cannot shoot. Interact actions validated server-side (distance via INTERACT_RANGE/VEHICLE_ENTER_RANGE/REVIVE_RANGE, line of sight via physics lineOfSight for pickups, life/mode state) — invalid ones are ignored silently.

- Hitscan with LAG COMPENSATION: rewind = clamp(sim time ms - input.rt, 0, MAX_REWIND_MS) / 1000; hitbox history ring buffer (HITBOX_HISTORY_MS) of every player pose per tick; rewindHitboxes interpolates poses between ticks and builds hitboxes via physics buildHitboxes. For each pellet: raycastWorld (range = weapon range) then test only candidate players near the ray (broadphase by distance from ray < 3 m, excluding shooter and teammates — friendly fire OFF, teammates do not block) using rewound hitboxes, and vehicles (raycastVehicle at current pose) -> nearest hit wins. Damage via items computeDamage/applyArmorDamage (falloff by distance), 50 percent weapon damage to vehicles. Ballistic weapons (hitscan false): spawn Projectile with vel = items launchVelocity(def, dir), rewind stored; each tick advance with stepBallistic in sub-steps (<= 1/120 s), segment-test world (raycastWorld over the segment) and players using hitbox history at (time - rewind), vehicles; remove on hit, after 3 s, or outside map. Damage distance = traveled. Frag: action throw (items.frag > 0, throwCooldown) -> projectile kind frag thrown along aim with upward bias at THROWABLES.frag.throwSpeed, bounces with damping off terrain/boxes, explodes after fuse: damage with linear falloff over radius to players with line of sight (and vehicles), explosion event, noise.

- Damage pipeline: hit events (to attacker + victim) with part, armor flags, result; stats (damage, headshots, shotsFired/shotsHit, longestKill). Health <= 0: if teamSize > 1 and the victim has at least one teammate alive and not downed -> life downed (downedHp DOWNED_HEALTH, knockCount++, bleed DOWNED_BLEED_PER_SEC * (1 + 0.5*(knockCount-1)), crawl at MOVE_SPEED.downedCrawl, cannot shoot/use/loot), knock event; damage to downed reduces downedHp (no armor); downedHp <= 0 -> dead (finished true if by damage, credit lastAttacker). Otherwise dead + kill event. When a team has no member alive (alive = life alive), all its downed members die and the team is eliminated: placement = (teams still in the game after elimination) + 1, teamEliminated event; dead players spill their inventory as loot (weapons with mags, ammo, consumables, frags, gear) in a small ring around the body. Win when <= 1 team remains: phase ended, placement 1 for the winners, matchEnd event with results(). Fall damage on landing: (landSpeed - FALL_DAMAGE_SPEED) * FALL_DAMAGE_PER_MS. Spectating: dead players automatically spectate a living teammate, else their killer; action spectate switches between valid targets.

- Revive: action revive with a downed teammate within REVIVE_RANGE while alive/not downed; continues while INTERACT held and the reviver does not move (mx/mz ~0) or shoot; after REVIVE_TIME target becomes alive with 10 health, revived event, stats.revives. Use items: action use (bandage/firstaid only below HEAL_CAP_PARTIAL, medkit below 100, energy below MAX_BOOST, fuel requires being in or within VEHICLE_ENTER_RANGE of a non-destroyed vehicle that is not full) -> UseState; cancelled by fire, reload, slot switch, jump, sprint, cancel action; on completion applyConsumable (or refuel +50 percent fuelMax) and remove the item; events useStart/useDone. Pickup action -> items pickupItem; leftover count stays on the ground; replaced weapons/gear are dropped as loot at the player. Drop / dropWeapon / swapWeapons actions. tickBoost every tick.

- Vehicles: create from world.vehicleSpawns (cap MAX_VEHICLES, seeded fuel 30-90 percent). Actions enter (nearest free seat, driver preferred; specific seat optional), exit (vehicles exitPosition; bailing out above 8 m/s deals (speed-8)*3 fall damage), seat (switch to a free seat). Occupants ride at seatWorldPosition with mode vehicle; driver controls: throttle = mz, steer = mx (right positive — check the vehicles module convention and map correctly), handbrake = JUMP or HANDBRAKE bits, boost = SPRINT or BOOST bits. stepVehicle each tick; crashes -> crashDamage to vehicle and occupants (vehicleCrash event); run-over: moving vehicles (> 4 m/s) hitting players on foot (vehicleHitsPoint) deal damage scaling with speed credited to the driver and knock them aside; vehicle health 0 -> burning 5 s -> explosion (radius 6 m, damages occupants and nearby, vehicleDestroyed event) and the wreck stays; deep water stops vehicles. Training: destroyed vehicles respawn at their spawn after 10 s.

- Loot: initial spawn from world.lootSpawns (about 75 percent occupied, tier-based via items rollLoot with a seeded Rng, small offsets so stacks do not overlap); spatial hash grid (16 m cells) kept in sync on add/remove for lootNear; loot delta tracked for drainLootDelta. playersNear/vehiclesNear via a per-tick player grid.

- Training mode (config.mode training, world kind training): phase playing immediately; players spawn at world.training.spawn (spread out), full kit not given; action give (training only, rate-limited) adds the item (weapons with full mag, ammo stacks of 60, etc.); action respawn resets to spawn with full health; death auto-respawns after 3 s; infiniteAmmo: magazines refill on reload without consuming reserve and reserve never decreases; zone disabled (no damage, stage final with huge radius); no plane. Targets: bullets hitting WorldBox kind target produce a targetHit event (private to shooter) with distance from shooter, damage (as computeDamage with no armor), part head if the hit point is in the top 22 percent of the box. Moving targets (TrainingTarget kind moving: ping-pong between a and b at speed; deterministic from sim time; expose function trainingTargetPosition(target, timeSec) so the client renders the same) are hit-tested as standing hitboxes and also emit targetHit.

- Noise events (shots with weapon loudness, explosions, vehicles every ~0.5 s with radius 150, footsteps of sprinting players radius 30) kept for 3 s for bots. Events -> SimEvent audiences: hit -> [attacker, victim]; targetHit, pickup, useDone private; shot range 1100; impact range 300; reload/draw/useStart/dryfire range 150; land/jump/jumpPlane/chuteOpen/throw range 250; vehicle events range 500; explosion range 1200; knock/kill/revived/teamEliminated/zonePhase/planeStart/matchStart/matchEnd global.

- MatchRunner per ARCHITECTURE.md: maps clients to players; start(now) adds players (team from client or auto), fills bots if config.botFill, calls sim.start(), sends matchInit (MatchInit) to every client. update(now): fixed-step accumulator (TICK_MS, max 5 catch-up ticks, then drop the backlog), each tick: botDriver.update(TICK_DT) then sim.step(); route sim events into per-client outboxes filtered by audience (private ids, or range from the client viewpoint = their player position, or the spectated player when dead). Snapshots at SNAPSHOT_RATE per client: phase, alive, teamsAlive, zone, plane, self (SelfState of the client player, full detail), players with relevance-band rates (RELEVANCE_BANDS by distance from viewpoint; self, teammates and anyone who damaged/was damaged by the client in the last 2 s always every snapshot), dead players only for 5 s after death then listed in gone, vehicles (same banding), projectiles within 800 m, events, loot delta. Quantise positions to cm, angles to 1e-3 rad. Never send enemy hp/dhp or anyone else inventory (anti-cheat information hiding). handleMessage: input -> token bucket (rate TICK_RATE*INPUT_RATE_SLACK per second, burst INPUT_BURST), drop duplicates/old seq, queue at most MAX_INPUT_QUEUE (drop oldest), sim.queueInput (also enforce in GameSim). ping -> pong {c, s: sim time ms}. leaveMatch -> removeClient. onEnd fires once when sim.isOver(). stats() reports tick timing.

- Performance: a 64-player match (bots via a trivial test driver) must step in < 8 ms average per tick in Node; measure in a test (assert < 20 ms to avoid flakiness) and optimise (grids, scratch vectors, no closures per tick).

- Tests (tests/sim.test.ts, tests/runner.test.ts) with real Stage A modules and a scripted bot-free setup: shooting a stationary enemy with the AR at 20 m deals expected damage and a hit event; armor reduces it; lag compensation: target moving sideways, shot with rt 200 ms in the past at the old position hits, rt older than MAX_REWIND_MS is clamped; sniper projectile has travel time and drop (hit at 300 m arrives ~0.4 s later); fire rate cannot exceed weapon rpm even with input every tick; recoil accumulates server side regardless of client aim; downed -> revive flow; bleed out; team elimination, placement and winner; zone timeline and damage outside; plane -> jump -> freefall -> auto chute -> landing; pickup rejected beyond range or through a wall; vehicle enter/drive/fuel/crash damage/exit; training targetHit and give/respawn; runner: matchInit contents, snapshot never includes enemy hp or others inventory, input flood is rate limited (feeding 100 inputs in one message batch / tick does not move the player faster than sprint speed), events private routing; determinism: two sims with the same seed and inputs produce identical state.
