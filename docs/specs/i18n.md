- Plurals: t(key, { count }) picks key + "_" + Intl.PluralRules(lang).select(count) if that key exists, else key + "_other", else key. Provide _one/_other in en (and the right categories for ru (_one, _few, _many, _other), ar (_zero,_one,_two,_few,_many,_other) etc. — every locale must contain the same KEY SET as en, so put plural category variants needed by any language into en too (en can map extra categories to the same text). Interpolation "{name}" replaced by params; numbers formatted with Intl.NumberFormat for the language.

- For THIS stage, the 9 non-English locale files must contain full real translations of every key (natural, game-appropriate wording, not machine-literal; keep placeholders intact; keep proper nouns like DROPZONE). Arabic must read naturally right-to-left.

- initI18n(): language from localStorage key "dz.lang" if valid, else first supported match from navigator.languages (match by primary subtag, e.g. pt-BR -> pt, zh-CN/zh-TW/zh-Hans -> zh), else en. Factor the selection into a pure exported function pickLanguage(stored: string | null, navLangs: readonly string[]): Lang for tests. Apply document.documentElement lang and dir when document exists (guard for non-DOM). setLanguage persists (guard localStorage access with try/catch), applies, re-runs translateDom(document.body) and notifies listeners. translateDom fills elements with data-i18n (textContent), data-i18n-title, data-i18n-placeholder, data-i18n-aria (aria-label), with optional data-i18n-params JSON. fmtDuration m:ss with locale digits where natural (Intl), fmtNumber via Intl.NumberFormat.

- scripts/check-i18n.ts (run with npx tsx): (1) every locale has exactly the en key set; (2) every translation has the same {placeholder} set as en; (3) scans src/client/**/*.ts (excluding src/client/i18n/locales) for hardcoded user-facing strings: assignments to .textContent/.innerText/.innerHTML/.placeholder/.title/.alt or setAttribute("title"|"placeholder"|"aria-label"|"alt", ...) whose right-hand side is a string or template literal containing letters (template literals that only interpolate expressions/whitespace/digits/symbols are fine; innerHTML templates are flagged if their static parts contain alphabetic words outside of tag names/attributes — keep a practical heuristic), and alert/confirm/prompt calls with string literals; lines with the comment i18n-ignore are allowed. Print violations with file:line and exit 1 if any; exit 0 otherwise.

- Tests (tests/i18n.test.ts, Node env): key parity for all locales; placeholder parity; pickLanguage cases (stored valid/invalid, pt-BR, zh-TW, ar-EG, unknown -> en); t interpolation and plural selection for en/ru/ar; LANGUAGES has 10 entries and ar is rtl; check script logic can be exercised on a fixture string (export the scanner function from the script or a helper module and test it detects el.textContent = "Hello" and ignores el.textContent = t("x")).

## UPDATE (parallel build) — overrides conflicting points above
- The English dictionary is composed from fragments: `src/client/i18n/locales/en.core.ts` (your core keys)
  merged with `uiStrings` from `src/client/ui/strings.en.ts` (owned by the UI agent, keys `ui.*`) and
  `feelStrings` from `src/client/feel/strings.en.ts` (owned by the feel agent, keys `feel.*`).
  `src/client/i18n/locales/en.ts` must be: `export const en = { ...enCore, ...uiStrings, ...feelStrings } as const;`
  and `TKey = keyof typeof en`. Those two fragment files already exist as empty stubs; do NOT edit them.
- Non-English locale files are typed `Partial<Record<TKey, string>>` during the parallel build; `t()` falls back
  to English for missing keys. Translate ALL of your core keys into the 9 languages now. The final i18n pass
  (later) translates `ui.*` / `feel.*` keys.
- `scripts/check-i18n.ts` must enforce completeness of every locale against the full merged `en` key set
  (it will report missing ui/feel translations until the final pass — that is expected) plus placeholder
  parity and the hardcoded-string scan. Support `--keys-only` and `--scan-only` flags.
- `tests/i18n.test.ts` key-parity tests apply to the core key set (`en.core.ts`), not the fragments.
