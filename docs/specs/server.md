# Module spec: server

Owned paths: src/server/** and tests/server.test.ts, tests/cheats.test.ts

- MODULE: Game server (src/server) per ARCHITECTURE.md Stage B. Node 22 + ws. Entry src/server/index.ts: when run directly (tsx src/server/index.ts) starts the server (PORT env or DEFAULT_SERVER_PORT, LAG_MS env, logs), and also exports startServer(opts) for tests (port 0 = random). HTTP: GET /healthz -> 200 json {ok, lobbies, players, uptime}; in production serve static files from dist/ with correct content types, SPA fallback to index.html, path traversal safe, cache headers for hashed assets. WebSocketServer on path /ws with maxPayload MAX_MESSAGE_BYTES, perMessageDeflate off.

- Connections: every message JSON.parse in try/catch -> validateClientMessage (src/shared/validate.ts); invalid -> error net.badMessage, after 10 invalid messages within 10 s close with kick. Token-bucket rate limit per connection on total messages (e.g. 60/s sustained, burst 120; input messages are additionally limited inside MatchRunner) -> error net.rateLimited, persistent abuse -> kick. Must hello first (version check -> net.versionMismatch). Heartbeat: ws ping every 10 s, terminate if no pong for 30 s. Client ids random (crypto.randomUUID).

- Lobbies (LobbyManager + Lobby classes): createLobby (creator becomes host and member of team 0), listLobbies (summaries, newest first, only waiting/in_game status, hide empty), joinLobby (errors lobby.notFound / lobby.full / lobby.inGame), leaveLobby (host migration to the oldest member; delete when empty), lobbySettings (host only, validated; adjust teams if teamSize changes; kick-free: members keep but teams reassigned to fit), setTeam (lobby.teamFull when team has teamSize members; teamCount = ceil(maxPlayers/teamSize)), ready toggle, startMatch (host only; every non-host human must be ready -> lobby.notReady; with botFill false need >= 2 humans), chat (broadcast within lobby, sanitized). Broadcast lobbyState to members on every change and lobby list updates to clients not in a lobby (throttled).

- Match: on start create MatchRunner({config: {mode: br, seed: random 32-bit, maxPlayers, teamSize, botFill, botDifficulty, zoneSpeed, infiniteAmmo: false}, clients: members mapped with their chosen teams, botDriverFactory: createBotDriver from src/shared/bots, onEnd}) — make the runner factory injectable (startServer opts.runnerFactory) so tests can use a fake runner. A single shared loop (setInterval 4 ms or setImmediate-based high-resolution scheduler) calls runner.update(performance.now()) for all running matches. Route client input/ping/leaveMatch messages to the runner of their lobby. On match end: send matchOver with results to members still connected, keep the runner alive ~8 s so final snapshots flow, then dispose, lobby status waiting, reset ready flags, send backToLobby + lobbyState to members. Disconnect during match -> runner.removeClient (bot takes over) and lobby membership removed. leaveMatch -> client goes back to the lobby room view (backToLobby + lobbyState) while the match continues for others.

- LAG_MS: symmetric artificial latency for BOTH directions per connection, order-preserving (queue with timestamps), plus optional jitter 0. Log per-match tick stats every 30 s (runner.stats()). Graceful shutdown on SIGINT/SIGTERM.

- Do not trust anything from the client: names sanitized (sanitizeName), lobby names, chat; caps on lobbies (e.g. 200) and members.

- Tests: tests/server.test.ts — start server on port 0 with a fake runnerFactory (records messages; can simulate end) and real ws clients: hello/version mismatch; create/list/join/full/inGame errors; teams/teamFull; host-only settings/start; notReady; chat sanitized; start -> fake runner created with correct config and client teams; input routed; match end -> matchOver, backToLobby, lobbyState with ready reset; host migration; disconnect cleanup; /healthz; LAG_MS delays both directions (measure round trip of ping/pong >= 2x lag). tests/cheats.test.ts — with the REAL MatchRunner (from src/shared/sim; it is written concurrently: if it is not importable yet when you run, structure the test so it is correct per the contract and run it again later; your final report must say whether it passed): raw ws client joins lobby with botFill false + a second client, starts a match, then sends: speed-hack input flood (many inputs per message and many messages) -> after 2 s of sim time the player moved no farther than sprint speed allows; fire-rate spam (FIRE toggled every input) -> shotsFired never exceeds rpm budget (observe via self stats in snapshots); pickup action for a loot id far away -> not picked up; NaN/huge values/unknown fields -> rejected, connection eventually kicked if spammed; oversize payload -> connection closed; teleport attempt is impossible since positions are never accepted (document). Keep tests fast (< 60 s total).
